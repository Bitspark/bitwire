# bitwire 0.6.0

The hydrated contract lets service adapters express messages with live sending
capabilities nested alongside ordinary Ontos values. All eight native
presentations declare the value, tuple, wire and endpoint views and opaque
composition-established receive context. A conveyed endpoint grants sending;
receive and closure ownership remain with its original owner.

Go and TypeScript provide one pure `bitwire/hydrated/1` codec for structural
atoms, tuples and reference descriptors. Body, reference and frame pack/unpack
operations validate complete inputs with explicit inclusive node, tuple-depth
and byte bounds. Reference path metadata consumes bytes without adding semantic
nodes or tuple depth. Ordinary data resembling references remains ordinary data.

The codec follows accepted [decision 0019](../decisions/0019-hydrated-wire-protocol.md)
and its unchanged independently derived vectors. Runtime construction, allocation,
proxy forwarding, reference liveness and cleanup belong to bitruntime; this
release is the shared interface and format dependency for that implementation.
It introduces no RPC engine, carrier-specific hydrated interface or compatibility
reader. Ground Wire, addressed access, exact paths and Ontos bytes are unchanged.

Validation includes the fixed vectors, symmetric exact/one-over boundaries,
immutable capture, deep/shared inputs, malformed whole-frame rejection, all
native declarations and packaged consumers, and fresh Go/npm installation.
The release process requires a successful rehearsal at the exact integration
commit before its immutable tag and public publication. Runtime and routed
service acceptance are reported by their own repositories.
