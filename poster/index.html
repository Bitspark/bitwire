Bitwire

One interface for sending a message to a path. Components that speak it can be plugged into larger systems without knowing where they were plugged in.

Plugging in is exact. Selecting a path or mounting components gives back the same interface, under written laws that eight language packages share and that independent test cases check against a production runtime.

Released as 0.2.0 for Go, TypeScript, Python, Rust, Swift, C++, Java and Haskell. Nightseam v0.6.0 has adopted it in Go and TypeScript. Declarations only: runtimes supply endpoints.

paths

A path is a strip of opaque segments

Every figure on this page draws a path this way: a bar for the origin, then one cell per segment. These four look alike, and are four different paths.

[]

No segments: the origin itself.

[""]

One segment, the empty string. A valid child name.

["a/b"]

a/b

One segment. The slash is just a character.

["a", "b"]

ab

Two segments.

Nothing is parsed, normalized or inherited: "é" written as one code point and as e plus a combining accent are different segments, and reaching a path grants no permission beneath it.

send

Follow one send down an assembly

Each boundary tears off exactly one segment and hands the same message on. The cart at the bottom sees only its own path; it never learns where it was mounted.

  1. Callerholds checkout, a Wire selected from the system
    cartadd

    checkout.send(["cart", "add"], m). The caller does not know that checkout points into a larger system.

  2. Selectioncheckout = at(system, ["shop"])
    shopcartadd

    On a send, selection puts its prefix in front. That is all it does.

    at(at(w, a), b) ≃ at(w, a ++ b)

  3. systema mount of shop and its siblings
    shopcartadd

    A mount consumes exactly one segment and delegates the same message to that child. It creates no peer, channel or queue.

    at(mount({k: w}), [k]) ≃ w

  4. shopa declared composite: an origin that answers "Bookshop", children cart and recommendations
    cartadd

    A composite routes named children the same way. Each child is complete access, passed on untouched: selecting ["cart"] gives exactly the cart.

  5. cartan endpoint's single receiver
    addmessage(["add"], m)

    The path arrives relative to the cart's own origin, with the unchanged message m. Move the cart under another name and nothing here changes.

  6. Replythrough m.return
    bypasses every boundary

    The cart answers through the message's own return capability. Nothing above rebuilt m, so the reply reaches the original caller directly.

attach

Attach through your language's package

The packages are declarations; none depends on a runtime, transport or generator. Your code depends on the interface. Endpoints come from a runtime such as Nightseam; send-only composition takes a few lines of your own.

TypeScript

compiled and run
npm install @bitspark/bitwire@0.2.0
import type { Message, Path, Wire }
  from '@bitspark/bitwire';

// Send-only selection: put the prefix in
// front, hand on the very same message.
function at(wire: Wire, prefix: Path): Wire {
  return {
    send: (path, msg) =>
      wire.send([...prefix, ...path], msg),
  };
}

// Any send access will do. This one prints.
const shop: Wire = {
  send: (path, msg) =>
    console.log(path, msg.frame.kind),
};

const m: Message = { frame: {
  version: 1, kind: 'request', id: 'c:1',
  params: { item: 'notebook' },
} };

at(at(shop, ['cart']), ['add']).send([], m);
at(shop, ['cart', 'add']).send([], m);
at(shop, []).send(['cart', 'add'], m);
Output 
[ 'cart', 'add' ] request
[ 'cart', 'add' ] request
[ 'cart', 'add' ] request

Three spellings, one path: the selection law, observed. Compiled with tsc --strict against the 0.2 declarations. This at only sends. A view that also receives needs a dispatcher that owns the endpoint's one attachment, which a runtime supplies.

rules

Four rules that change how you build on it

  1. 1

    Send means admitted, not done.

    Send returns when the message is accepted or refused. It never runs the receiver's code on your stack or waits for a reply, and a receiver's callback returning does not finish an invocation.

  2. 2

    An endpoint has one receiver.

    A second attachment is refused; it does not replace the first. Route tables, prefix matching and precedence belong to a dispatcher composed above, which owns that one attachment for all its views.

  3. 3

    A Wire grants sending, nothing more.

    Receive and close belong to Endpoint. If a holder must not reach them, hand out a send-only facade: a type annotation does not hide methods. Closing a mount never closes what it borrowed.

  4. 4

    Pass messages on; never rebuild them.

    Composition hands on the same message object, so the return capability's identity and the runtime's received context survive. Neither is ever serialized: only frame fields cross a network hop.

limits

Where Bitwire stops

Bitwire owns what the interface means. What makes messages actually move lives in the projects that depend on it: decision 0010 puts the implementations in bitruntime, and using Bitwire never requires Nightseam.

Not in this repository

  • An endpoint runtime, queue, transport or codec.
  • A generator.
  • A new network protocol. Messages keep the nightseam.duplex/1 profile, which moves here as bitwire/1 with the same bytes.
  • Authentication. Reaching a path is not permission.
  • Routing policy or a completion signal in the primitive.
  • Profile negotiation. Deployments agree on a revision out of band.

A shared signature is not interoperability

Two adapters must also agree on operation paths, profile revision, value encoding, contract identity, reference scope and authority. Mounting a storage API at ["worker"] does not make it a worker.

Frames, composite laws, native spellings and contributor commands

The four frames

The Wire path is the operation name, so a frame never carries a second one. Every frame is version 1. Payloads are JSON; a missing value and JSON null are different.

KindRequiredOptional
Requestrequest id, JSON paramstrace fields, string metadata
Responserequest id and exactly one of JSON result or public errortrace fields
EventJSON datatrace fields, string metadata
Cancelrequest idtrace fields

Declared-composite laws (decision 0006)

For a composite c = compose(o, m) with origin o and children m; ⊥ refuses every send.

(S0) at(w, [])             ≈ w
(S1) at(at(w, p), q)       ≈ at(w, p ++ q)
(S2) at(c, [k])            ≈ m[k]     k ∈ dom m
(S3) at(c, [k])            ≈ ⊥        k ∉ dom m
(O)  origin(c)             ≈ o
(R0) compose(parts(c))     ≈ c
(R1) parts(compose(o, m))  ≅ (o, m)
(M)  mount(m)              ≈ compose(refuse, m)

Segments map to keys by exact UTF-8. Construction refuses a missing origin or child, an invalid segment and duplicates. parts belongs to whoever built the composite; an arbitrary Wire is not decomposable.
